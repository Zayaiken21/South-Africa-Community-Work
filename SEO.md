# Search engines, sitemap and app stores

Everything below is generated by `frontend/build.mjs` every time the site is built — nothing to edit by hand.

## What the site gives search engines

| File / tag | What it does |
|---|---|
| `sitemap.xml` | Every public page with when it last changed, how often it changes and how important it is. |
| `robots.txt` | Lets every crawler in, keeps the team dashboard and private support threads out, and points to the sitemap. |
| `llms.txt` | A plain summary of the site and its common questions for AI assistants and answer engines. |
| Page titles and descriptions | A unique title and description on every page. |
| `canonical` + `hreflang en-ZA` | Tells Google the main address of each page and that it's for South Africa. Help points to Support so they aren't counted twice. |
| `robots` meta | Public pages are indexed with large image previews; personal pages (profiles, saved jobs, job details, dashboard) are not. |
| Open Graph + Twitter cards | The title, description and 1200×630 image shown when a link is shared on WhatsApp, Facebook, X or LinkedIn. |
| Structured data (JSON-LD) | Organization and site search on the home page; every page described with breadcrumbs; the Support page lists 30 common questions and answers (FAQ); the CV builder is a free web app. |
| Fallback content | People and crawlers without JavaScript still get each page's heading, text and links to every public page. |

## Do this once: Google Search Console and Bing

1. Open https://search.google.com/search-console → **Add property** → **URL prefix** →
   `https://zayaiken21.github.io/South-Africa-Community-Work/`.
2. Verify with the **HTML tag** method: copy the `content="…"` code it gives you and send it to me (or add a
   `<meta name="google-site-verification" …>` tag to `frontend/build.mjs`), then press **Verify**.
3. **Sitemaps** → enter `sitemap.xml` → **Submit**.
4. Bing: https://www.bing.com/webmasters → **Import from Google Search Console** (one click).

## About robots.txt on GitHub Pages

Search engines only read `robots.txt` at the very top of a domain. This site lives in a folder
(`zayaiken21.github.io/South-Africa-Community-Work/`), so for now the sitemap is submitted directly in Search Console
(step 3 above) and the page tags do the work. It starts working on its own when either:

- you use a custom domain (e.g. `communitywork.co.za`) — recommended for search and for the app stores, or
- you copy `robots.txt` into the root of a repository called `Zayaiken21.github.io` (the same repo PLAY_STORE.md uses
  for `assetlinks.json`).

## App stores (Google Play now, Apple later)

The site is already an installable app (manifest, service worker, icons, screenshots in `assets/screenshots/`).

- **Google Play:** follow `PLAY_STORE.md` (PWABuilder → Android package → upload). Needs `.well-known/assetlinks.json`
  at the domain root.
- **Apple App Store:** in https://www.pwabuilder.com enter the site address → **Package for stores → iOS**. It gives
  an Xcode project to upload with a Mac and an Apple Developer account (US$99 a year). Apple asks that apps do more
  than show a website — the accounts, shifts, escrow payments and support here count. For links that open the app,
  add `.well-known/apple-app-site-association` at the domain root (PWABuilder gives you the file).
- Store listings use the same name, description, icons and screenshots as the site, so they stay consistent.
